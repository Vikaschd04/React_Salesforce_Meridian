Read this honestly: the reference build running today is a B2C storefront — it proves the platform end to end (catalog, cart, payments, orders, OMS, service, real-time). Everything tagged Roadmap is the B2B layer that sits on top of that foundation. The layering, order pipeline and payment abstraction do not change to support it.

Why headless, and why no Commerce Cloud licence

B2B Commerce is a licensed product that ships an opinionated storefront. This pattern reaches the same buyer outcomes using the CRM data model you already own.

The data model is already there

Accounts, contacts, price books, orders, quotes, approvals and cases are core platform objects — not Commerce Cloud features. A storefront can read and write them directly through the API.

One system of record

Orders placed on the web land as the same Order records your sales team sees. No sync job, no second catalog, no reconciliation between commerce and CRM.

The head is disposable

React today, a mobile app or a punch-out catalog tomorrow. The BFF contract stays fixed, so a new channel is a new client — not a new integration.

The three layers

Each layer talks only to its neighbour. The buyer's browser never sees Salesforce; Salesforce never renders a page.

The B2B buying journey

A sequence, because each step gates the next. Solid steps run today; dashed steps are the B2B additions — note that they extend the same pipeline rather than replacing it.

Buyer signs in Roadmap

Contact resolves to their company Account, buyer role and spend limit.

Entitled catalog Roadmap

Account's BuyerGroup scopes which products are visible.

Contract pricing Roadmap

Their negotiated Pricebook2 is resolved — the catalog already reads a price book, so this swaps the input.

Build the order Live

Browse, guided selling, bundles, or a quick-order pad; cart persists per buyer.

Quote (optional) Roadmap

Large baskets become a Quote; a rep prices it and the buyer accepts.

Approval gate Roadmap

Orders above the buyer's limit route to an approver via Flow before activation.

Price & pay Live

Totals recomputed from Salesforce, then card — or, on the roadmap, PO / Net-30 invoice.

Order written Live

Order + OrderItems created and activated in Salesforce.

Fulfil & serve Live

OMS summary, live status back to the buyer, and any issue opens a Case.
